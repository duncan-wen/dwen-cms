# Shipping

How a change reaches `main`.

**Branches, review, merge**: a spec's tickets ship together on one **integration branch** named `<feature-slug>`, off a freshly fetched `origin/main`. Build each ticket on its own branch `<feature-slug>-<NN>` (in a worktree when several are ready at once) and merge it back into the integration branch once `pnpm check` and `pnpm smoke` pass. After the first merge, open one draft PR with `gh pr create --draft --base main`; CI fails a PR whose base is anything else, since a PR merged into another branch never reaches `main`. When every ticket is done, run `/code-review` against `origin/main` and fix what it finds, then show the Owner the screenshots (see **Screenshots**), mark the PR ready, and merge it with `gh pr merge --merge` once the Owner says OK and its checks pass. The `Vercel` check passing means the build, and with it the content check, succeeded. The Vercel preview is optional for the Owner; to check a path on it yourself, take the URL from the Vercel bot's comment (`gh pr view <N> --json comments --jq '.comments[].body' | grep -o 'https://[a-z0-9-]*\.vercel\.app'`) and send `x-vercel-protection-bypass: $VERCEL_AUTOMATION_BYPASS_SECRET` (from `.env.local`).

**One-off changes**: a change outside a spec (a retro, a one-off fix) gets its own branch off `origin/main`, e.g. `retro-<feature-slug>-<NN>`, and its own PR; run `/code-review` against `origin/main` and fix what it finds, then show the Owner the screenshots and merge once they say OK and its checks pass.

**Screenshots**: before ticking a box about how a page looks, or showing the Owner a visual change, run `pnpm shots <path>…` and read the screenshots. It builds `e2e/content`, shoots each path in light and dark at 1280px and 375px into `test-results/shots/`, crops each visible Illustration and Diagram on its own, writes `test-results/shots/index.html` with every shot on one page (the crops under their page's full shots), asks for reduced motion so an animation shows its finished frame, and fails if a page scrolls horizontally or a box other than a code block clips its content, sideways or downwards. `--content content` shoots the real content instead of `e2e/content`. `/posts/typography-sample` holds every prose element. The Owner reviews from that page: give them `explorer.exe test-results/shots/index.html` to open it.

**After merging**: wait for `main`'s production deployment (`gh api repos/duncan-wen/dwen-cms/commits/main/status --jq .state` reads `success`), then, from the scratchpad, read its errors: `vercel --scope team_dUM4e6kZ7gTvxEVRfG8zGjpi logs --project dwen-cms -e production --query 'level:error' --since 55m --json`. Each line's `data.deploymentId` says which deployment logged it; compare with the `id` from `vercel inspect duncan-wen.aibbm.org`, and tell the Owner about any error the new deployment logs. The Hobby plan keeps under an hour of logs, so a longer `--since` fails, and the MCP's `get_runtime_errors` answers 403.

**Preview env vars**: the Vercel CLI is logged in. Run `vercel link --yes --project dwen-cms` from the scratchpad, never the repo (linking writes `.vercel/` and edits `.gitignore`). A variable scoped with `--git-branch` needs that branch pushed first, and the push's own deployment starts before the variable exists, so `vercel redeploy` it once the variable is added.
