# Owner 操作手冊

這份手冊寫給網站的 Owner（Duncan），說明怎麼新增、修改和移除網站上的內容。詞彙沿用 [`GLOSSARY.md`](../GLOSSARY.md)；規則一律以 `src/content/content.ts` 的內容檢查為準。

## 先懂這三件事

1. **沒有後台。** 每篇文章就是 repo 裡的一個資料夾 `content/posts/<網址代號>/`，內文寫在 `index.mdx`，用到的圖片也放在同一個資料夾。網址代號（Slug）就是資料夾名稱，例如 `why-mdx-in-git`，文章網址是 `/posts/why-mdx-in-git`。
2. **草稿就是還沒合併的 PR。** 文章沒有「草稿」或「已發布」欄位：PR 開著的時候讀者看不到，合併進 `main` 的那一刻就是發布。
3. **只有你能發布。** Writing Agent 只會開草稿 PR，不會自己合併。agent 會等你說 OK 才合併。

## 你的工作只有兩件

1. 打開截圖頁看：
   - 文章頁面：`explorer.exe test-results/shots/index.html`
   - 文宣圖：`explorer.exe promo/index.html`
2. 回覆「OK」，或直接說哪裡要改。

開分支、寫檔案、跑檢查、開 PR、合併，都是 agent 做的。

## 每種操作怎麼做

所有操作都是：**跟 Claude 說要做什麼 → agent 開草稿 PR、附截圖 → 你看截圖說 OK → agent 合併 → 網站更新**（Vercel 會在一兩分鐘內部署好）。

| 你要做的 | 跟 Claude 這樣說 | 讀者看到什麼 |
|---|---|---|
| 新增文章 | 「寫一篇文章：我怎麼用 MCP 接本機工具」 | 合併後出現在首頁、文章列表、標籤頁、RSS 和 sitemap |
| 修改草稿 | 在同一個對話裡直接說要改哪裡 | 還是看不到，直到合併 |
| 放棄草稿 | 「這篇不要了，關掉 PR」 | 什麼都不會出現 |
| 勘誤 | 「修改 why-mdx-in-git：第二段錯字」 | 內容變了，但不顯示更新日期 |
| 改版 | 「why-mdx-in-git 補一段效能比較」 | 文章顯示「更新於 日期：說明」 |
| 換網址 | 「why-mdx-in-git 的網址改成 mdx-in-git」 | 新網址；舊網址自動轉過去 |
| 移除 | 「移除 why-mdx-in-git 這篇」 | 原網址顯示「文章已移除」 |

### 新增文章

給一個題目就好。可以順便講你要的角度，或你自己的經歷（例如「花了一個月」「當時很挫折」）。agent 用 `write-post` skill 照下面的步驟走：

1. 依題目選文風：技術文用「硬核實戰派」；職涯、心態、投資用「生活沉澱派」；旅行、家庭用「感性紀實派」。三種文風的範例原文都收在 `.claude/skills/write-post/SKILL.md`。
2. 寫文章，講流程或架構的地方會畫 Mermaid 圖。
3. 跑三道檢查：`pnpm content:check`、`pnpm check`、`pnpm build:check`。
4. 產生文宣圖：大部分文章用等高線版，介紹流程的用流程圖版，講寫程式的用終端機版。
5. 拍文章截圖，開草稿 PR。

PR 說明裡會有「請 Owner 確認」：agent 查不到的個人細節（花了多久、當時的感受）都列在那裡，不會自己編。請逐條確認或改寫。

### 修改已發布的文章

修改分三種，agent 會先判斷是哪一種，你也可以直接指定。

- **勘誤**：錯字、壞掉的連結、換句話說但意思不變、換一張修好的圖。讀者看不出有改過，不留日期。
- **改版**：會改變讀者學到的東西，例如新增段落、改了建議、修正事實或數字、更新過時的結果。文章上會顯示「更新於」加一句說明，原本的發布日期不變。
- **換網址**：資料夾改名，舊網址記在 `previousSlugs`，自動永久轉到新網址，舊連結不會失效。

分不清是勘誤還是改版時，就問：讀過舊版的人會想知道這次改了什麼嗎？會的話就是改版。

### 移除文章

agent 會刪掉文章資料夾（圖片一起刪），再把網址記到 `content/taken-down.yml`。之後原網址會回應 410（文章已移除），文章也會從列表、標籤頁、RSS 和 sitemap 消失。

移除是**永久**的：

- 沒有「暫時下架、之後再上架」。
- 移除過的網址不能再給新文章用。
- 只想改內容的話，請用勘誤或改版。

## 其他內容

- **關於頁**：放在 `content/pages/about/index.mdx`。跟 Claude 說「改寫關於頁」就好，流程和文章一樣，但頁面不會出現在文章列表，也沒有日期。目前的內容還是佔位文字，可以請 agent 照你的文風改寫。
- **標籤**：核准清單在 `content/tags.yml`，文章只能用清單裡的標籤。需要新標籤時，agent 會在同一個 PR 裡加進清單並寫明理由，你合併就等於核准。標籤一律用小寫英文，讀者看到的標籤頁只會列出至少有一篇文章用到的標籤。
- **文宣圖**：已發布的文章也能重新產生，說「幫 why-mdx-in-git 產生文宣圖」即可。agent 會在 `promo` 設定裡選版型、決定標題斷行和重點，再執行 `pnpm promo <網址代號>`。圖片在 `promo/` 資料夾，不會進 git。
- **封面**：沒設定的文章會依網址代號自動產生等高線封面。想用照片的話，把照片放進文章資料夾，跟 agent 說「封面用這張」。

## 想自己動手改

也可以不透過 agent：

- **GitHub 網頁**：打開 `content/posts/<網址代號>/index.mdx`，按鉛筆圖示編輯，選「Create a new branch」開 PR。CI 會跑同樣的內容檢查，沒通過會顯示錯在哪個欄位、要怎麼改。
- **本機**：改完後執行 `pnpm content:check`，錯誤訊息會指出檔案、欄位和規則。

自己改時要注意：改版要記得在 `revisions` 加一筆，換網址要記得加 `previousSlugs`。不想記這些規則的話，直接請 agent 處理比較快。

## 目前做不到的

- 排程發布：合併當下就上線。文章的 `date` 只是顯示用的發布日期，不會延後上線。
