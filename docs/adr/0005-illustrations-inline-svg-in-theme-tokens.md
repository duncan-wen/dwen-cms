# Illustrations are hand-written SVG, inlined at build time, coloured only by the site's theme tokens

An Illustration is an SVG file the Writing Agent writes by hand into the Post's folder and references like any image; the build inlines it into the page instead of loading it through `<img>`, and its colours are limited to named site tokens (the neutrals, the accent, and four series colours borrowed from the code highlighting), which the content check enforces by refusing any literal colour. An `<img>` SVG can't see the page's CSS, so it couldn't follow the light/dark theme the way Diagrams do; purpose-built MDX components (a thread timeline, a memory layout) draw more reliably but need code before every new kind of picture; and extending Mermaid's diagram types still couldn't show things like a race condition. Inline SVG with tokens lets the agent draw anything while staying in the site's colours in both themes. Since nothing but code may scroll sideways, an Illustration too wide for a phone comes with an upright phone copy the agent draws too, rather than shrinking its labels out of reach. The cost: every Illustration is written against this token vocabulary, so changing it means redrawing them; a hand-drawn picture is only as good as the agent's eye, so the screenshots in both themes are its review; and a picture that keeps recurring should graduate to a component rather than be redrawn each time.
