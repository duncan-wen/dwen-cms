# Hand-written content rules, packages for commodity features, no blog template

We didn't start from a Next.js blog starter (such as tailwind-nextjs-starter-blog or Vercel's portfolio starter), although one would have shipped rendering, Tags, RSS and dark mode on day one. The site's value is the content rules a Writing Agent's Draft must pass: approved Tags, Slug history with redirects, Takedowns answering 410, Revisions vs. Corrections. No starter has these, and bolting them onto a starter's own content layer costs more than one small content module we own, which also keeps the codebase small enough for agents to read whole. The flip side: commodity features carry no project rules, so they come from Next.js built-ins (`sitemap.ts`, `opengraph-image`) or a maintained package (a feed library, a theme toggle) rather than being hand-written.
